# B 分支：单测、验收与风险

本清单对应 [系统设计](SYSTEM_DESIGN.md) 与 [接入说明](INTEGRATION.md)。B 分支已添加新的纯规则单测；下列页面链路和真机验收仍按表逐项执行。旧版测试已移除。

## 1. 怎么分配测试

| 层级 | 重点 | 方法 |
|---|---|---|
| 纯 Kotlin 单测 | A/B 频次、三次上限、共享日额度、时间边界 | 传入固定时间、时区、配置、记录，不等待真实天数 |
| 页面结果单测 | 请求码和访问标记匹配、消费一次、激活页中转 | 测试小型回传逻辑；涉及 Activity 回调可用 Robolectric |
| 管理器单测 | 展示记次、点击停止、被拦截后无补弹、存储失败 | Fake 时钟、存储、Dialog 展示回调、deeplink 打开器 |
| Android 集成 / 真机 | ARouter 与系统返回关系、手势、ViewPager、UI 宿主 | 实际打开并逐层返回，使用项目测试时钟 |

不为任意中间页编写引导测试。挑选两层真实普通页面证明“关键页打开更多页面后返回”即可。

## 2. 频次单测

除特别声明，enable=true、当前有新的有效返回、宿主正确、没有其他弹窗。每项分别验证允许 / 拒绝及记录是否按预期变化。

| 编号 | 输入 / 操作 | 预期 |
|---|---|---|
| F01 | 新数据，首次有效返回 | 立即允许对应类型 |
| F02 | enable=false；之后改 true 但没有新返回 | 首次拒绝；更新配置不补弹 |
| F03 | A 已 1 次，距上次 first 间隔少 1ms | 拒绝，不修改次数 |
| F04 | A 已 1 次，恰好达到 first 间隔且跨日 | 允许第 2 次 |
| F05 | A 已 2 次，距上次 second 间隔少 1ms / 恰好达到 | 分别拒绝 / 允许第 3 次 |
| F06 | A 已 3 次，第三间隔缺失 / 0 / 30 / 极大值 | 全部拒绝，不存在第 4 次 |
| F07 | 对 B 重复 F03–F06 | 规则一致，读取 B 自己的记录 |
| F08 | A 已 3 次，B 为 0 次，其他限制允许 | B 可以首次展示 |
| F09 | A 昨日展示；B 今日展示；A 今日冷却到期 | A 被共享日额度拒绝 |
| F10 | A 今天展示；B 首次有效返回 | B 仍被共享日额度拒绝 |
| F11 | A 昨日 23:59 展示；B 次日 00:00 返回 | B 可首次展示；日限制不是滚动 24h |
| F12 | A 昨日 23:59 展示，first=1；A 次日 00:00 返回 | A 冷却未满 24h，拒绝 |
| F13 | 间隔为 0，当天再访问 / 次日重新访问 | 当天日额度拒绝；次日可继续下一次 |
| F14 | 当前阶段所需间隔缺失、负数、乘法溢出 | 拒绝本轮，不按零处理 |
| F15 | 首次展示，但 first / second 尚未配置 | 无首次冷却；其他限制通过则允许 |
| F16 | 系统时间早于已记录的最近展示 | 拒绝，不清零记录 |
| F17 | 夏令时切换日，first=1 | 始终比较固定 24h，日额度另按日历日期 |
| F18 | A stopped=true，B=false，日期允许 | A 永久拒绝；B 正常判断 |

`thirdPopInterval` 的解析兼容用例在配置层测试：JSON 有 / 无该字段都得到相同业务规则；它不是第四次弹窗开关。

已编码的核心规则测试位于 `widget-guide/src/test/java/com/carrie/widgetguide/GuidePolicyTest.kt`，使用固定时钟验证首次、两个冷却边界、两类独立三次上限、共享自然日、点击停止、零间隔、无效配置与时间回拨。其余表项是后续页面集成及真机验收标准。

## 3. 返回链路与机会消费测试

本节重点观察管理器被请求的次数；即使由于频次没显示，也要确认本轮只请求一次。

| 编号 | 操作 | 预期 |
|---|---|---|
| R01 | 首页搜索按钮 → 结果 → 系统返回 | 首页检查 A 一次 |
| R02 | 首页 → 激活 → 结果 → 激活 → 首页 | 只在首页检查 A，激活页不弹 |
| R03 | 首页 → 激活 → 首页 | 无有效访问标记，不检查 |
| R04 | 激活页去游戏 / 视频，最后返回首页 | 没有结果页则不检查 |
| R05 | 搜索历史、猜你想搜、电影电视、综艺各入口去结果页 | 分别能逐级回传，返回首页检查 A |
| R06 | 结果页 → 普通页 1 → 普通页 2 → 原栈返回首页 | 中间页面未接入引导也成立 |
| R07 | 一次激活页内搜索两次再返回首页 | 检查 A 一次 |
| R08 | 暗词实际进入结果 / 普通资讯 | 前者 A；后者不弹 A/B |
| R09 | 我的 → 书签，切历史 tab，访问更多页再返回 | 只在我的检查 A 一次 |
| R10 | 我的 → 下载 → 更多页 → 原栈返回我的 | 我的检查 A |
| R11 | 首页 → 扫一扫，未扫成功直接返回 | 具有访问标记即可检查 A，保留原业务取消结果 |
| R12 | 首页 AI → 资讯 → 更多页 → 原栈返回 | 首页 AI 检查 B |
| R13 | AI 搜 → AI 二级 → 资讯 → 更多页 → 原栈回二级 | 二级页检查 B；再回 AI 搜不再检查 |
| R14 | AI 搜 → AI 二级 → AI 搜，无资讯 | 不检查 B |
| R15 | 关键页恢复但还没返回入口 | 不提前弹窗 |
| R16 | requestCode 不匹配、标记不匹配、data=null | 不检查，不吞原业务结果 |
| R17 | 同一个已消费结果重复回调 | 管理器最多被请求一次 |
| R18 | 冷却未到被拒绝；推进时钟，留在首页或普通 onResume | 不补弹；重新完成访问并返回才再检查 |
| R19 | 云配关闭 / 每日限制 / UI 占用被拒绝；之后条件解除 | 不补弹，必须新一轮行为 |
| R20 | 冷启动、进程被杀后恢复旧栈和旧结果 | 无本轮等待关系，不弹 |
| R21 | 旋转发生在关键页访问期间 | 普通 ViewModel 保留在途关系，正常返回不重复消费 |
| R22 | 回调早于 onPostResume | 恢复时只消费一次；频次拒绝后 pending 为空 |
| R23 | 返回交接时页面离开 / 展示 tab 不符 | 放弃，不等待切回；A/B 不互相兜底 |
| R24 | 路由失败 / 中断 / 连点 | 失败清理等待状态；连点只建立一个在途请求 |

对 R18/R19 使用 Fake 时钟：先触发并断言未显示；只推进时间、切 tab、刷新云配，断言展示调用数仍为零；然后再次访问并返回，才允许变为一。这比只测试 canShow 的时间表达式更能验证“机会不保留”。

## 4. 弹窗、存储与设置测试

| 编号 | 操作 | 预期 |
|---|---|---|
| U01 | Dialog onShow 一次 / 重复通知 | 只增加对应类型一次，更新对应时间和共享时间 |
| U02 | 展示前宿主失效或窗口创建失败 | 不计次，不遗留 busy 或待弹任务 |
| U03 | 空白取消 / 系统返回关闭 | 保留展示记录，stopped 不变 |
| U04 | A 左 / 右按钮；B 左 / 右按钮，各自测试 | 只停止对应类型，打开对应链接 |
| U05 | 任一添加 deeplink 抛异常 / 路由无法打开 | 对应类型仍停止，不能回滚 |
| U06 | 先点左按钮再快速点右按钮 | 只有一次停止处理和一次跳转 |
| U07 | 点击停止后重启应用再做新行为 | 对应类型不弹，另一类型按自身和共享限制判断 |
| U08 | 退出登录、切配置 | 本地计数与停止标志不重置 |
| U09 | 清除全部应用数据 | A/B 和共享记录恢复初始值 |
| U10 | 同时收到 A/B 尝试 | 至多一个 Dialog；第二次不排队、不留资格 |
| U11 | 展示写入未完成时取消；随后新返回 | busy 保持到必要写入结束，不产生并发记录覆盖 |
| U12 | SP/MMKV 读损坏或写入失败 | 不清零伪装新用户，本进程暂停自动引导，记录错误 |
| U13 | Dialog 显示后旋转或进程恢复 | 原引导不自动重建，不重复计次 |
| U14 | 荣耀 / 非荣耀设备打开设置 | 仅荣耀出现 item；不影响自动弹窗的设备范围 |
| U15 | 设置手动进入添加界面 | A/B 次数、时间、停止标志全部不变 |
| U16 | 两处 B 入口跨天分别访问 | 共用 B 记录，不是各三次；A 的三个入口同理 |

测试 U04/U05 时还需断言调用顺序：内存停止 → 尝试持久化停止 → 尝试 deeplink；链接是否成功不影响停止值。记录当前实例失败处理，不能用“链接打不开所以未添加”取消停止。

## 5. 真机验收顺序

开发验证面板先打开自动弹窗并点“应用云配”，随后点“查看弹窗本地数据”。第一次使用时原始键值为空属于正常现象。返回首页后完成新的搜索结果访问并沿原栈返回；弹窗显示后再进入记录页，检查 `common_tools_widget_show_count = 1`、对应时间和 `last_any_widget_guide_shown_at_millis`。首页次数文字在 SP 提交成功后刷新。若没有弹窗，记录页首行会指出最后到达的返回链路节点或频控拒绝原因；没有收到结果回调时，首行停留在“打开 ... 等待返回”，可据此检查业务页的 result 与路由 requestCode。打开该记录页不会清除任何数据或消耗展示次数；按钮可手动重新读盘。

1. 使用独立测试数据，开云配，完成一次搜索返回，确认 A 出现在首页非 AI tab 底部。
2. 当天访问 AI 资讯并返回，确认 B 被共享日限制挡住；推进测试日期后静留页面仍不弹，再次访问返回才检查 B。
3. 清理测试数据后分别验证工具、扫一扫、AI 二级列表路径。AI 二级列表返回时即可弹 B，AI 搜不弹。
4. 分别验证搜索激活直接返回、游戏 / 视频路径、暗词到资讯路径、冷启等反例。
5. 按测试时钟验证第 2 / 3 次边界和第 4 次永不出现；改变 third 配置不能改变上限。
6. 左 / 右添加都验证实际快服务链接；故意用无法打开的测试链接验证停止仍生效。
7. 普通返回键、返回手势、工具栏返回各跑一轮；书签历史左右滑动不提前触发。
8. 验证屏幕旋转、后台恢复、小屏大字体、系统导航栏遮挡、截图比例和两个按钮位置。
9. 在荣耀与非荣耀设备验证设置入口；点击后比对引导存储完全不变。

测试时钟和清状态功能只在 Debug 使用，不改变系统时钟；正式逻辑仍使用设备时间。新测试命令和通过结果应在代码落地后补入本文，本次不引用旧测试的通过数量。

## 6. 风险与处理

| 风险 | 影响 | 简单处理 / 验证 |
|---|---|---|
| 结果字段被原业务后续 setResult 覆盖 | 合法访问不弹，或破坏扫码结果 | 合并原结果组装函数；保留 resultCode，并用取消扫码场景回归 |
| 暗词 deeplink 分发丢失 requestCode | 无法收到真实结果或误判入口 | 在已有分发器保留结果关系；最终目标写标记；分别测试结果与资讯落点 |
| 某路由使用不同任务栈或复用方式 | 原栈返回回调不符合预期 | 检查这几个相关路由的 launchMode / flags；本方案按普通栈工作，不全局追踪 |
| onActivityResult 早于宿主可显示；AndroidX Lifecycle 状态派发与 onPostResume 的先后不同 | 合法结果可能被状态检查丢弃，次数始终为 0 | 使用 Activity 实际 onResume/onPostResume 回调维护可见标记；只交给紧接着的恢复回调一次，并在记录页暴露最近一次拦截原因 |
| 在 onResume / onArrival 直接弹 | 冷启、后台恢复或跳转时误弹 | 展示必须由已匹配的本轮结果驱动；对应反例集成测试 |
| 延迟回调 / 生命周期泄漏 | 已销毁 Activity 被持有或跳转 | 无在途关系则忽略结果，切主线程复核宿主；记录操作不捕获长期 Activity |
| 手机时间或时区被手动更改 | 冷却延长或自然日变化 | 采用设备时钟；时间倒退保守拒绝；次数不重置；不宣称本地策略能防改时钟 |
| 显示窗口后立刻进程崩溃 / 断电 | 计数写入可能未完成 | 尽快顺序写入；明确窗口和磁盘非原子，不承诺异常断电下严格恰好一次 |
| 停止标志写入失败 | 重启后可能无法保留永久停止 | 本进程停止自动引导并记录错误；不能把磁盘失败说成已持久化成功 |
| 多进程或多个管理器改同一文件 | 次数与共享限制竞争 | 仅主进程单实例管理此功能；不让多个页面独立创建存储管理器 |
| 系统备份恢复旧记录 | 卸载重装可能带回历史状态 | 本地频次文件按项目备份策略排除；清除应用全部数据的验收单独执行 |
| 荣耀识别或快服务链接差异 | 设置项显示不准 / 添加页打不开 | 用现有设备工具和正式链接，在目标机型测试；失败不解除停止 |
| 仓库仍有废弃源码 | 误认为运行 Demo 就是 B 的行为 | README 明确文档阶段；后续替换旧链路与测试后再宣告实现完成 |

关键不确定项集中在现有 deeplink 分发器、页面实际承载方式、项目 Promise 封装和正式快服务资源。这些属于接入核对点，不改变本文已确定的业务规则，也不要求记录全应用所有页面。
