# 桌面组件引导：B 分支方案

**当前采用 B 分支的简化设计：ARouter 打开页面，系统返回 / `finish()` 返回，相关页面逐级回传访问结果。**

原先的方案和开发方向废弃，后续工作在 `B` 分支继续。本次重写文档，尚未实现新的业务代码。仓库中继承的 Kotlin/XML 和旧测试属于废弃实现，不能用来证明 B 方案已实现或已验证。

## 阅读顺序

1. [系统设计与实现方案](docs/SYSTEM_DESIGN.md)：需求、触发流程、频次、本地存储、弹窗与边界。
2. [Kotlin + XML 接入说明](docs/INTEGRATION.md)：ARouter、返回结果、字段解释、生命周期和代码示例。
3. [单测、验收与风险](docs/ACCEPTANCE.md)：需要实施的测试及风险处理。

方案只需要三个部分：相关业务页面回传结果、一个引导管理器、一个复用的 XML 底部弹窗。任意中间页面保持原有导航，不需要记录所有页面，不需要维护全局页面栈。

每次满足访问条件并返回原入口，只检查一次。冷却或每日限额不满足就结束本轮，之后必须重新访问并返回。A、B 各自最多三次，各自点击添加后永久停止，合计本地自然日最多一次。设置入口单独处理。
